### 2. A failed OCC read is asked again by every company in a run: "read once a process, whatever the number of companies" holds only when the OCC answers · `P3`

**How sure:** high. Traced with the repository's `occFor`.

**Evidence**
- **A failure is not kept.** `cachedOccList` clears the cache when the read fails, so the next company's `occFor` asks again. check:occ pins this as intended: "a failure not kept: the next company asks again".
- **Both likely failures are `error`s.**
  - A count that is not a number, such as the OCC's home page after a redirect, is an `error`.
  - So is a timeout, after 120 s.
- **Nothing holds the other companies back.**
  - `shouldBackOff` holds a source back for every subject only after a `throttled` (`lib/ingest/store.ts`). An `error` holds back only the subject that had it.
  - `loadLastFetched` counts only `ok` and `empty`, so the source stays due for every company the next run.
- **The OCC has refused in exactly this shape.**
  - "apps.occ.gov answered both requests with a 'Security Redirect'" (`docs/proposals/2026-10-28-proposals.md`).
  - "apps.occ.gov (302 to the OCC's home" (`docs/proposals/2026-11-09b-proposals.md`).
  - Today occ.gov answered two of this audit's HEAD requests with a 302 to `https://www.occ.treas.gov/`.
- **Trace:** fetch serves the OCC's home page as a 200 HTML answer. `occFor` for five companies in one process made five count requests, each answered "error: the OCC's count is not a number".

**Failure case:** a refresh run is 200 companies by default (`scripts/refresh.ts`), and runs are hourly (README).
- While the OCC redirects us, each run asks the count 200 times: about 400 requests with the redirect hops, and about 4,800 a day.
- If the host stops answering instead, each company waits 120 s: 6.7 hours a run.

The quota note says "read once a process, whatever the number of companies" (`lib/ingest/quota.ts`).

**What a fix would need:** keep a failed read as the process's answer for the rest of the run, so the next run asks again. Alternatively, report a redirected or non-JSON answer as `throttled`, so the source-wide back-off applies. Then change check:occ's "the next company asks again".

*Importance:* low to medium: no wrong row, but repeated requests to a federal host that is refusing us, the pattern NC-143 fixed for GDELT · *Efficiency:* a few lines · *Practicality:* easy.
